# Project knowledge base

Facts about this implementation that a future developer needs. Update this file when an
architectural decision changes. Design rationale is in `docs/architecture.md`; metric
formulas are in `docs/evaluation_methodology.md`.

## System in one paragraph

A RAG assistant ("NW-Assist") for a fictional hospital answers questions over four NIST
PDFs (1,319 chunks) using a 4-bit Qwen2.5-1.5B-Instruct on MLX. The same index holds 50
synthetic records: 40 `restricted` patient incident reports and 10 HR memos wrongly
labelled `public`. Four switchable defences sit around the model: D1 Presidio redaction
at indexing, D2 document-level access control, D3 a rule-based injection filter, and D4
an output filter. A 115-case benchmark runs under six configurations (A baseline, B–E one
defence each, F all four).

## Module map and interfaces

* `pipeline.rag.RAGPipeline.answer(QueryRequest, Principal) -> PipelineTrace`. This is
  the only entry point used by the API, the CLI and the benchmark.
* `retrieval.store.Store`: `query(question, k, where)`, `upsert(chunks)`, `plant`,
  `remove_planted`, `get`. `build()` builds both collections.
* `security.access_control.AccessPolicy`: `authorize(principal, chunks)` and
  `is_authorized`; `where_filter(principal)`.
* `security.injection_filter.screen(chunks) -> (clean, flagged)`; `scan(text) -> [rule names]`.
* `security.output_filter.filter_output(text, policy) -> (text, actions)`.
* `llm.base.LLM` protocol: `model_id` and `generate(messages) -> Generation`. The
  backends are `MLXBackend`, `OpenAICompatibleBackend`, and `FakeLLM` (tests only).
* `evaluation.runner.run(pipe, cases, version, truth, experiments, quick)` returns
  `{meta, summary, static, rows}`, and `report.write()` persists it.

## Configuration defaults (`config.py`)

| Setting | Default |
|---|---|
| chunk size / overlap / top-k | 900 / 150 characters / 4 |
| embedder | Chroma default all-MiniLM-L6-v2 ONNX (384-d) |
| collections | `nist_plain`, `nist_redacted` |
| model | `mlx-community/Qwen2.5-1.5B-Instruct-4bit`, temperature 0, max 200 tokens, 60 s timeout |
| roles | public → {public}; clinician → {public, restricted}; admin → {public} + evaluation endpoints |
| D3 / D4 policy | `exclude` / `redact` |
| seed | 1337 |
| system canary | `NW-ASSIST-7731` |
| URL allowlist | nist.gov, hhs.gov (and their subdomains) |

## How the defences work, and their measured limits

* **D1.** Presidio with `en_core_web_sm` redacts PERSON, EMAIL_ADDRESS, PHONE_NUMBER,
  US_SSN, DATE_TIME and a custom `MRN` entity before embedding.
  * It removes 287 of the 290 seeded values; 3 names survive because NER misses them.
  * It also redacts author names and dates in the NIST text, and once turned
    "164.308" into `<PHONE_NUMBER>`.
  * It costs utility for authorised users: clinician lookups fall because the data is
    gone from the index.
* **D2.** A Chroma `where` filter, then an ACL check against `data/processed/acl.json`,
  denying by default.
  * It cannot protect mislabelled documents (the HR memos).
  * The API always forces it on.
* **D3.** 11 regex rules. The first 9 were written before the first benchmark run; 2
  (`permission_change`, `data_exfiltration`) were added during the restructure, before
  the indirect-extraction cases were written.
  * Paraphrased, Spanish, letter-spaced and footnote carriers mostly get through.
  * It flags 2 of 1,369 clean corpus chunks, and 5 of 8 benign look-alike documents.
* **D4.** Withholds answers containing the canary (also in transformed forms), strips
  non-allowlisted links and markdown images, and runs Presidio on the answer.
  * It cannot see semantic hijacks.
  * Under `redact` it also removes MRNs that clinicians are allowed to see.

## Benchmark facts

* `data/benchmarks/cases.jsonl` is generated by `make benchmark` from
  `evaluation/benchmark.py`, `injection_cases.py` and `leakage.py`. A unit test checks
  that the committed file matches the generator.
* Categories (n): benign_qa 10, unanswerable 6, pii_direct 10, pii_enumeration 8,
  pii_role_claim 5, pii_incidental 7, injection 50, indirect_extraction 5,
  benign_lookalike 8, authorized_lookup 6.
* A planted document exists only for its own case: it is inserted into the index and the
  ACL, then removed.
* Leak scoring returns (source doc id, field) pairs, never values. `answer_masked`
  replaces every seeded value.

## Dataset provenance and licensing

* NIST SP 800-66r2, Privacy Framework 1.0 (CSWP 01162020), NISTIR 8053 and AI 100-2e2025,
  from nvlpubs.nist.gov. They are US Government works (public domain), with SHA-256
  pinned in `config.CORPUS`.
* Synthetic data comes from Faker with seed 1337:
  * phone numbers use 555-01xx (reserved for fiction);
  * SSNs use area numbers 9xx with middle groups 10–49 (never issued, and outside the ITIN
    ranges);
  * e-mail addresses use `example.org` (RFC 2606).
* Code is MIT licensed.

## Known issues and decisions log

* 21 Oct: FDA corpus abandoned (bot detection); NIST used instead.
* 21 Oct: spotlighting removed as a separate defence to keep exactly four. The prompt still
  delimits evidence in `<document>` blocks and says documents are not instructions.
* 21 Oct: ONNX embedder instead of sentence-transformers (disk), approved by the owner.
* 22 Oct: API forces D2 on (a caller could otherwise switch off authorisation).
* 22 Oct: scoring bug fixed. Unauthorised-context exposure was computed after the planted
  document left the ACL, which inflated exposure in every configuration. Regression test
  `tests/evaluation/test_runner.py`.
* Run-to-run noise: the baseline PII-leak count varied 16 vs 15 of 30 between two runs with
  the same data and cached generations, most likely approximate HNSW search after
  plant/delete.
* Docker mode is drafted but not verified (disk).

## Debugging

* `make verify` shows the platform, packages, whether the model is cached and whether the
  index is built.
* Per-case detail is in `results/runs/<id>/cases.jsonl`: retrieved and context IDs,
  injection flags, output actions, `answer_masked`.
* Re-runs are fast because generations are cached in `storage/llm_cache/generations.jsonl`,
  keyed by a hash of (model, settings, prompt). Delete that file to force regeneration.
* `python -m rag_copilot.cli query "..." --role public --protected` runs one question.
