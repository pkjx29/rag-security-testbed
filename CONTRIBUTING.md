# Contributing

Read [KNOWLEDGE.md](KNOWLEDGE.md) before making a substantial change. It records how the
system actually works and why.

## Commands

```bash
make check            # ruff + mypy + pytest: must pass before every commit
make evaluate-quick   # smoke test of the benchmark through the real model (a few minutes)
make evaluate         # full benchmark; regenerates results/latest/
make benchmark        # only after editing case definitions; commit the new cases.jsonl
```

## Conventions

* Python 3.11+, type hints on public functions, `ruff` (line length 130) and `mypy` clean.
* Every number that affects results lives in `src/rag_copilot/config.py`.
* Each pipeline step stays a small function that can be tested on its own. Defence logic
  lives in `security/`, never inside retrieval or generation code.
* Tests: `tests/unit` (pure functions), `tests/security` (invariants, with `FakeLLM`),
  `tests/integration` (API with `TestClient`, a real temporary Chroma store). `FakeLLM` is
  for tests only. The application and the benchmark always use a real local model.
* Every security bug fixed gets a regression test.

## Security invariants (do not break)

1. The role comes from the API key or the harness, **never** from request text or headers.
2. Interactive `/query` always runs with access control on.
3. With D2 on, no chunk the ACL denies reaches the prompt, the citations or the logs.
4. Logs hold counts and IDs only. No raw personal values appear in logs, API errors or
   committed results.
5. Inference stays local. The HTTP backend accepts loopback or `host.docker.internal` only.
6. Only synthetic personal data, generated by `ingestion/synthetic.py`.

## Prohibited shortcuts

* Hand-editing numbers in `results/` or the README: every number must come from a run.
* Skipping or weakening a failing test, or switching off a check, to get a green build.
* Tuning `injection_filter.RULES` against individual benchmark cases. If a rule is
  added, record when and why in KNOWLEDGE.md, and re-run the look-alike false-positive
  check.
* Claiming HIPAA compliance, or that any filter catches all attacks.
